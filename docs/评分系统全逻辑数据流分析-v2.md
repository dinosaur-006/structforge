## 二、逐个系统详细分析

### 2.1 LLM 健康度评分 ✅ 正常

**数据流**:
```
pipeline.py → LLM 提取 VideoStructure
  → structure.health = {hook_strength, product_exposure_timing, selling_point_proof, pacing_compactness, cta_persuasiveness, overall}
  → 存入 DB analysis_result
  → 前端 HealthAssessment 组件展示 (雷达图)
  → 传入 LLM 迁移提示词 (original_scores)
```

**评分逻辑**: LLM 分析视频后自行判断。Doubao LLM 根据 prompt 中的评分标准给出 0-100 分。

**前端展示**: ✅ HealthAssessment 雷达图 + ScriptStructure 健康度标签

**判定**: **正常保留**。LLM 自主评分，非硬编码。对下游 LLM 迁移有参考价值。

---

### 2.2 BurstMetrics 预测评分 ⚠️ 前端已移除但后端仍在计算

**数据流**:
```
migrator.py generate() → BurstMetricsCalculator
  → predicted_scores (41指标规则引擎对新脚本的评分)
  → baseline_scores (参考视频评分)
  → 存入 script.metadata.predicted_scores / baseline_scores

前端: ❌ "AI 优化预估" 卡片已移除 → 数据未被消费
```

**评分逻辑**: 纯硬编码公式 (正则匹配 + 阈值判断 + 简单算术)。

**前端展示**: ❌ 已移除。数据仍在 metadata 中但从不读取。

**判定**: **废弃代码**。后端仍计算 ~200 行逻辑，产出数据无消费方。可删除 `migrator.py:196-257` 整块。

---

### 2.3 ResultEvaluator 版本对比 ⚠️ 前端部分移除

**数据流**:
```
migrator.py generate() → ResultEvaluator.evaluate_baseline()
  → ResultEvaluation {health, material_coverage, gap_count, cta_duration}
  → 存入 script_versions 表

ResultEvaluator.evaluate_script() → 对比基线
  → ResultVersion {score, metrics: {scoreDelta, materialCoverage, ...}, health, timeline}

前端: VersionTabs (分数徽章已移除 ✅, 名称仍显示)
      版本历史面板 (delta 已移除 ✅)
      侧边栏 "结构对比" (结构分已移除 ✅, 素材覆盖率/产品露出/缺口/CTA 保留)
      compareMode 雷达图 (health 对比保留)
```

**评分逻辑**: 规则引擎。`_evaluate()` 逐个检查：
- 素材覆盖率 = matched片数 / 总片数
- 产品首次露出时间
- 缺口数量
- CTA 时长

综合分 = 素材覆盖率×权重 + ... (规则计算)

**前端展示**: ⚠️ 综合分已从前端移除，但侧边栏的 4 个客观指标仍在。这些指标是事实数据（覆盖率=0% 意味着没有上传素材），非误导性评分。

**判定**: **保留但需清理**。侧边栏的素材覆盖率等是**客观结构对比**（非硬编码评分），有价值。`ResultEvaluator._evaluate()` 中的综合分计算仍在但前端不展示 → 可移除综合分计算逻辑。

---

### 2.4 BurstAuditor 审计 ⚠️ AnalyzePage 仍展示

**数据流**:
```
前端 AnalyzePage → POST /api/v1/audit/{jobId}
  → BurstAuditor.audit()
    → BurstMetricsCalculator (41指标规则引擎, 0ms)
    → 规则建议
    → 返回 FullAuditReport

前端 BurstAuditPanel:
  ✅ "综合爆款指数 40" → 已移除
  ✅ "全模态爆款审计报告" → 已改为 "视频结构分析报告"
  ⚠️ 单指标分数 (如 "镜头切换频率 16/100") → 仍展示
  ⚠️ 维度分数 (如 "注意力锚点 26") → 仍展示
  ✅ 详细 metrics 卡片 → 保留 (含 raw_value)
```

**评分逻辑**: BurstMetricsCalculator 纯硬编码。

**前端展示**: ⚠️ 综合分已移除，但单指标分仍在。每个指标附带 raw_value (如 "0.3次/秒") 提供上下文。

**判定**: **可保留**。单指标分数虽然也是硬编码，但附带具体的 raw_value，用户可以看到数据来源。维度分数同理。相比之前的 "综合爆款指数 40" 这种没有上下文的单一数字，现在展示的是有证据链的细化数据。

### 2.5 渲染自审计 ⚠️ 后端计算但前端仅展示部分

**数据流**:
```
render_pipeline.py _finalize()
  → BurstMetricsCalculator (对最终视频评分)
  → self_audit {overall_score, dimensions, visual_generation, audio_generation}
  → 存入 script.metadata.self_audit

前端 ResultPage "渲染质量" 卡片:
  ✅ visual_generation.method — 展示
  ✅ visual_generation.quality — 展示
  ✅ visual_generation.flux_segments — 展示
  ❌ self_audit.overall_score — 前端未展示 (浪费)
  ❌ self_audit.dimensions — 前端未展示 (浪费)
```

**评分逻辑**: BurstMetricsCalculator 纯硬编码。

**前端展示**: ⚠️ 仅展示 objective 数据 (flux_segments 计数, 方法名称)。BurstMetrics 评分数据未展示。

**判定**: **清理过时计算**。`overall_score` 和 `dimensions` 的计算可移除，保留 visual_generation 和 audio_generation 的客观数据。
