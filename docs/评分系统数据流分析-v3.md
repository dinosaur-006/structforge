## 二、数据流逐个追踪

### 2.1 LLM 健康度 ✅ 完整

```
生产: llm_structure.py (LLM prompt 要求输出 6 维健康度)
  → VideoStructure.health = {hook_strength, ..., overall}

消费1: migrator.py → prompt_context["original_scores"]
  → LLM 迁移提示词中显示原视频健康度

消费2: 前端 HealthAssessment 组件 (AnalyzePage)
  → 雷达图展示 6 维健康度

消费3: 前端 CompareRadar (ResultPage)
  → 版本对比雷达图

状态: ✅ 生产→消费 完整，无断链
```

### 2.2 版本对比 ⚠️ 部分展示

```
生产: result_evaluator.py → _evaluate()
  → ResultEvaluation {health, material_coverage, gap_count, cta_duration}
  → ResultVersion {score, metrics: {scoreDelta, materialCoverage, ...}, health, timeline}

消费1: 前端侧边栏 "结构对比" → materialCoverage, productExposure, gapCount, ctaDuration ✅
消费2: 前端 compareMode 视图 → original.score + currentVersion.score ✅ (仍在使用)
消费3: 前端 VersionTabs → 版本名称 (分数徽章已移除) ✅
消费4: 前端 版本历史面板 → 版本名称 (分数已移除) ✅

问题: ResultEvaluator._evaluate() 仍计算综合分 (score)，但该数值：
  - 前端 compareMode 中仍展示 ❗ (未移除)
  - VersionTabs 中已移除 ✅
  - 侧边栏中已移除 ✅

状态: ⚠️ compareMode 视图仍展示综合分数字。该分数是规则引擎计算，
      意义有限但用户仍可见。
```

### 2.3 审计面板 ⚠️ 指标分展示

```
生产: burst_auditor.py → BurstMetricsCalculator (41项规则)
  → FullAuditReport {overall_score, dimensions[{name, score, metrics[]}], suggestions, burst_template}

消费: 前端 BurstAuditPanel (AnalyzePage + StructureTabs)
  → "综合爆款指数" 大数字: ❌ 已移除
  → 维度分数 (如 "注意力锚点 26"): ✅ 仍展示 (带 raw_value)
  → 单指标卡片 (如 "镜头切换频率 16/100"): ✅ 仍展示 (带 evidence)
  → 模板参数: ✅ 仍展示

状态: ⚠️ 综合分已移除，但维度/指标分仍展示。这些分都是硬编码公式。
      每个指标附带 raw_value 和 evidence，可追溯到数据来源。
      对用户有一定参考价值但解释为"分数"可能误导。
```

### 2.4 渲染质量 ✅ 正常

```
生产: render_pipeline.py → _finalize()
  → self_audit {visual_generation, audio_generation, total_duration, segment_count}

消费: 前端 ResultPage "渲染质量" 卡片
  → vg.method (ComfyUI Flux / Prompt Card) ✅
  → vg.quality (excellent/good/basic/fallback) ✅
  → vg.flux_segments / audit.segment_count ✅
  → ag.method (Edge TTS / None) ✅

状态: ✅ 纯客观数据，无硬编码评分。生产→消费 完整。
```
