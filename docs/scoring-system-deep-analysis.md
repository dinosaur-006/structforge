# StructForge 评分系统深度分析报告

> 基于：32项 BurstMetrics 源码审查 + 行业最佳实践研究  
> 目的：找出评分系统的设计缺陷和改进方向

---

## 一、当前评分系统架构

### 1.1 整体结构

```
BurstMetricsCalculator (32项指标)
├── Dimension 1: Hook (注意力锚点) — 10项
│   ├── Visual:  H-V1 镜头频率  H-V2 视觉冲突  H-V3 亮度突变  H-V4 推镜
│   ├── Audio:   H-A1 音量突变  H-A2 冲突词    H-A3 语速突增
│   └── Subtitle: H-T1 弹入动画  H-T2 字号突变  H-T3 高亮颜色
│
├── Dimension 2: Trust (信任梯度) — 9项
│   ├── Visual:  T-V1 产品特写占比  T-V2 演示场景  T-V3 对比画面  T-V4 细节展示
│   ├── Audio:   T-A1 数据证据    T-A2 真人证言   T-A3 逻辑链
│   └── Subtitle: T-S1 功效词标注  T-S2 信任标识
│
├── Dimension 3: Density (卖点密度) — 6项
│   ├── Visual:  D-V1 产品频率    D-V2 功能多样性
│   ├── Audio:   D-A1 卖点词频    D-A2 利益点前置
│   └── Subtitle: D-S1 卖点文案密度  D-S2 价格次数
│
├── Dimension 4: Pacing (节奏曲线) — 5项
│   ├── Visual:  P-V1 三段式节奏比  P-V2 转场多样性
│   ├── Audio:   P-A1 BGM情绪起伏  P-A2 卡点精度
│   └── Subtitle: P-S1 字幕出现节奏
│
└── Dimension 5: CTA (转化指令) — 6项
    ├── Visual:  C-V1 价格视觉元素  C-V2 视觉聚焦
    ├── Audio:   C-A1 行动动词      C-A2 紧迫感营造
    └── Subtitle: C-S1 价格锚定      C-S2 字号放大
```

### 1.2 评分流程

```
参考视频分析 → BurstMetricsCalculator(shots, asr, vision, rhythm, packaging)
  → calculate_all() → 32项指标
    → dimension_reports() → 5维报告(加权平均)
      → generate_auto_fix_patches() → RFC 6902补丁
        → burst_auditor LLM软分析
          → 前端 BurstAuditPanel 展示
```

## 二、与行业标准的差距分析

### 2.1 行业 5 大核心指标 vs StructForge

| 行业核心指标 | 重要性 | StructForge 当前 | 差距 |
|------|:--:|------|:--:|
| **Hook 有效性**（前3秒） | ⭐⭐⭐⭐⭐ | ✅ 10项指标，最完善的维度 | 几乎对齐 |
| **留存率**（完整观看比） | ⭐⭐⭐⭐⭐ | ❌ 无此项 | 🔴 缺失 |
| **互动率**（点赞+评论+分享+收藏） | ⭐⭐⭐⭐ | ❌ 无此项（分析的是参考视频，无互动数据） | 🟡 无法直接测量 |
| **分享速度**（分享/小时） | ⭐⭐⭐⭐⭐ | ❌ 无此项 | 🟡 无法直接测量 |
| **完播率**（完整观看/曝光） | ⭐⭐⭐⭐ | ❌ 无此项 | 🔴 缺失 |

### 2.2 关键发现

**问题 1: 缺失 "Retention 留存率" 维度**

这是行业公认仅次于 Hook 的第二重要指标。当前系统分析了"视频有什么"（镜头、文案、节奏），但没有分析"观众会留下吗"。虽然参考视频没有实时观看数据，但可以从结构特征推断留存风险点——比如连续3段同类型分镜可能造成流失。

**问题 2: 评分是"静态特征分析"而非"动态效果预测"**

32项指标全部在问"这个视频有什么"（有冲突词吗？有推镜吗？有对比画面吗？），而不是在问"这些特征会产生什么效果"。行业最佳实践是从特征→效果的因果链：冲突词多 → Hook停留率高 → 完播率提升。

**问题 3: 权重系统过于简化**

`PlatformWeights` 只对8个指标做了平台差异化，其余24个指标权重全为1.0。实际平台算法远比这复杂——抖音对"分享率"的权重是点赞的4-6倍，小红书对"评论互动"的权重极高。

### 2.3 各维度具体问题

#### Hook 维度（最完善，但有3个问题）

| 问题 | 详情 |
|------|------|
| H-T2 "字号突变" 固定50分 | 无法实际测量字号变化，给出无意义的中等分数（污染平均值） |
| H-V3 "画面亮度突变" | 仅检查前2帧的 dominant_colors 是否不同——实际很少有数据，多数返回"未检测到" |
| Hook段判定硬编码3秒 | Hook不一定是严格3秒。有些视频Hook 1.5秒效果更好。应基于节奏曲线动态判定 |

#### Trust 维度（中等，有2个问题）

| 问题 | 详情 |
|------|------|
| T-A3 "问题→方案逻辑链" | 判定过于粗糙——只要 `asr_segments >= 3` 就给80分。可以检查 ASR 文本中是否真的存在"问题描述→产品作为解决方案"的逻辑 |
| 缺少"社交证明"指标 | 行业顶级视频都有社交证明元素（销量数字、用户评价、KOL背书），当前无此项 |

#### Density 维度（有1个问题）

| 问题 | 详情 |
|------|------|
| 卖点词库偏美妆护肤 | `SELLING_POINT_WORDS` 全是 "美白/抗皱/保湿/控油…"，对食品、数码、家居品类完全不适用 |

#### Pacing 维度（有2个问题）

| 问题 | 详情 |
|------|------|
| 只检查"快-慢-快"一种模式 | 实际爆款节奏模式多样："慢-快-快"（悬念型）、"快-快-慢"（冲击型）、"快-慢-快-慢-快"（情绪过山车型） |
| P-A2 "卡点精度" | 仅检查 rhythm 前5个点中是否有 cut≥3，过于粗糙 |

#### CTA 维度（有2个问题）

| 问题 | 详情 |
|------|------|
| CTA区域硬编码"最后5秒" | 行业最佳实践是"70%-80%位置"放置CTA，而非绝对的最后5秒 |
| 缺少"评论引导"指标 | 2025年算法趋势：评论互动引导（"哪个颜色好看？👇"）的权重超过直接CTA |

## 三、评分与产品其他模块的脱节

### 3.1 评分→迁移的断层

`_build_audit_summary` 将评分数据传给 LLM 迁移 prompt，但传递方式是：

```python
weaknesses = [{"dimension": "cta_persuasiveness", "score": 55, "weakness": "CTA段文案缺乏具体行动指令"}]
```

问题：LLM 看到"CTA段文案缺乏具体行动指令"，但不知道 32 项指标中有 6 项 CTA 指标，具体是哪一项弱（C-A1行动动词？C-S1价格锚定？）。LLM 需要在信息不完整的情况下猜测改进方向。

### 3.2 评分→渲染的断裂

`_finalize` 中的自审计评分与 `BurstAuditPanel` 展示的评分**使用同一套 BurstMetricsCalculator**，但自审计的输入数据（vision_frames）是渲染后从 segments 拼凑的，不是真实的视觉分析数据。这意味着自审计的准确性取决于 segments 的 visual 字段质量，而非实际生成的 ComfyUI 图片质量。

### 3.3 用户看到的分 vs 实际评的分

用户在 `BurstAuditPanel` 看到的5维雷达图和 32 项明细是针对**参考视频**的评分，而非针对**生成的新视频**。生成后的视频只在 `_finalize` 中做了快速自审计，不在前端展示。用户看不到"我的新视频比参考视频提升了什么"的对比。

## 四、改进方案

### P0 — 必须修（影响评分准确性和用户体验）

| # | 改进 | 问题 | 工时 |
|:--|------|------|:--:|
| 1 | **移除假指标** | H-T2(字号突变) 和 C-S2(字号放大) 永远返回固定分，污染平均值 | 0.5h |
| 2 | **卖点词库品类化** | SELLING_POINT_WORDS 按品类分库：美妆/食品/数码/家居 | 1h |
| 3 | **CTA位置动态化** | CTA 判定从 "最后5秒" 改为 "最后20%-30%时长" | 0.5h |
| 4 | **新增"留存风险"维度** | 基于结构特征推断留存风险点（连续同类型→流失风险） | 2h |
| 5 | **自审计结果前端展示** | `_finalize` 的自审计结果存入 script.metadata，前端展示新视频 vs 参考视频对比 | 1h |

### P1 — 应该修（提升评分专业性）

| # | 改进 | 问题 | 工时 |
|:--|------|------|:--:|
| 6 | **信任维度增加"社交证明"** | 检测销量/评价/KOL/排名等社交证明信号 | 1h |
| 7 | **Pacing 支持多模式** | 不只 "快-慢-快"，增加 "悬念型" "冲击型" "情绪过山车型" | 1.5h |
| 8 | **LLM 迁移 prompt 传递具体指标明细** | 不再只说"CTA弱"，而是说"C-A1行动动词指标=0分，需要增加'点击/抢/下单'等词" | 0.5h |
| 9 | **Hook 段判定动态化** | 基于 rhythm 数据和镜头切换频率动态判定 Hook 边界 | 1h |

### P2 — 锦上添花

| # | 改进 | 工时 |
|:--|------|:--:|
| 10 | 平台权重细化（抖音/小红书/视频号差异化 32 项而非 8 项） | 2h |
| 11 | 新增 "Loop 优化" 指标（视频是否设计为可循环播放） | 1h |
| 12 | 评分历史追踪（同一项目多次生成的评分变化曲线） | 1.5h |

## 五、P0 实施细节

### P0-1: 移除假指标

```python
# burst_metrics.py: 将 H-T2 和 C-S2 标记为 "experimental" 并从 dimension 平均分计算中排除
# dimension_reports() 中过滤掉 metric_id 在 {"H-T2", "C-S2"} 的指标
```

### P0-2: 卖点词库品类化

```python
CATEGORY_WORD_BANKS = {
    "美妆": ["美白", "抗皱", "保湿", "控油", "修护", "滋养"],
    "食品": ["酥脆", "浓郁", "鲜嫩", "爆汁", "拉丝", "Q弹", "入口即化"],
    "数码": ["降噪", "续航", "快充", "轻薄", "高清", "防水"],
    "家居": ["去污", "除菌", "收纳", "折叠", "静音", "速干"],
    "通用": SELLING_POINT_WORDS,
}
```

### P0-4: 新增"留存风险"维度

```python
# 基于结构特征推断留存风险:
# - 连续3段同类型 → 高风险
# - 无Hook段 → 极高风险
# - 最后2秒无CTA → 结尾流失风险
# - Product段超过10秒 → 中段流失风险
```

---

> **总结**: StructForge 的评分系统在"电商短视频特征分析"方面已经相当全面（32 项指标、5 维度、平台加权）。最大差距在于：(1) 2 项假指标污染分数、(2) 缺失"留存风险"维度、(3) 评分与产品其他模块的联动不够、(4) 评分是静态特征分析而非动态效果预测。P0 5 项改进可在大约 5 小时内完成，显著提升评分专业性和用户体验。
