# 视频优化全链路方案 v3

## 修订历史

| 版本 | 修订内容 |
|------|---------|
| v1 | 初版：诊断三大核心问题，提出 4 Phase 方案 |
| v2 | 融入专业评审：新增 Phase 0 动态结构、多模态镜头理解、音频驱动转场、LUT 色彩、人工审核 |
| v3 | 细化工程细节：结构约束条件、音频置信度降级、跨音频卡点、转场克制规则、产品色保护、全片字幕策略 |

---

## 一、当前核心问题诊断

### 问题 1：渲染决策链错误

当前渲染决策链采用简单的优先级降级（shot_pool → AI视频 → 卡片），但**没有基于原始视频分析结果来做决策**。正确的做法应该是：

```
Phase 0: LLM 动态生成最优脚本结构（含约束条件）
              ↓
分析原视频 → 得出评分(哪些维度弱)
              ↓
         针对每个分镜做决策：
         ├─ 这个分镜在原视频里表现好？→ 直接用原视频片段
         ├─ 这个分镜结构不对需要重排？→ 从原视频镜头池重组
         ├─ 这个分镜内容完全缺失？→ AI生成新视频
         └─ 兜底：动画卡片
```

### 问题 2：字幕策略错误

当前把 AI 生成的 `script` 文案当做 ASS 字幕叠加在视频上，这是错误的：
- **script 文本**：是给 TTS 配音用的——语音模型读出 "家人们直接炸了！" 这样的口语化文案
- **屏幕字幕**：应该是精简的关键词、卖点标签、价格信息，而不是整段语音文案

### 问题 3：视频编辑能力缺失

当前渲染只做简单 concat。真正的视频优化需要镜头拆分、多模态理解、重组编排、音频驱动转场、色彩统一。

---

## 二、分镜级决策矩阵

每个分镜的处理方式由**原视频评分**和**素材可用性**共同决定：

| 原视频该维度评分 | 有匹配的原始镜头？ | 决策 | 渲染方式 |
|----------------|-----------------|------|---------|
| ≥70（好） | 有 | 保留 | 直接用原视频对应片段 + 静音原音轨 + 混入TTS |
| ≥70（好） | 无 | 重组 | 从其他时间段的相似镜头裁切 |
| 40-69（一般） | 有 | 优化 | 原镜头 + 变速/裁切 + LUT 统一调色 |
| 40-69（一般） | 无 | 重组+补全 | 镜头池重组 + 关键帧动画填充 |
| <40（差/缺失） | — | AI生成 | Seedance 生成新视频 |

## 三、详细实施方案

### Phase 0：动态结构优化

**目标**：在做任何渲染之前，先由 LLM 分析产品类型和目标人群，动态生成最优视频脚本结构。

**v3 新增：结构约束条件**

LLM 的自由发挥必须在平台规则的框架内。Prompt 中加入硬约束：

```
约束条件（必须遵守）：
1. 总时长必须在 18-30 秒之间
2. 首段必须是 Hook 类，时长不超过 3 秒
3. 末段必须是 CTA 类，时长不超过 4 秒
4. 段落总数在 3-8 段之间
5. 每个段落的 type 必须从以下集合中选取：
   [hook, pain, product, proof, cta, compare, demo, scene, offer, result, tutorial, attract]
6. 如果产品有价格优惠信息，必须包含 offer 段
7. 如果产品需要展示使用效果，必须包含 demo 或 result 段
```

**实现方案**：

```
输入: 产品名称 + 卖点 + 目标人群 + 原视频分析结果
  │
  ├─ LLM 分析：
  │   产品类型（美妆/3C/食品/服装/...）
  │   卖点性质（外观/功能/性价比/品牌/...）
  │   目标人群（年轻女性/商务人士/学生/...）
  │   平台特性（抖音快节奏/小红书精致/B站深度/...）
  │
  └─ LLM 输出动态结构（在约束条件内）：
      外观型美妆: Attract(2s)→Visual(6s)→Tutorial(8s)→Result(3s)→CTA(2s)
      功能型3C:   Hook(2s)→Problem(4s)→Compare(5s)→Demo(6s)→Offer(3s)→CTA(2s)
      食品饮料:   Hook(1.5s)→Scene(5s)→Product(4s)→Proof(3s)→Offer(2.5s)→CTA(2s)
```

### Phase 1：多模态镜头理解

**目标**：将镜头标注从"纯视觉"升级为"视觉+音频+上下文"多模态融合。

**v3 新增：音频置信度评分与降级策略**

```
每个镜头的分析输入：
  ├─ Vision 分析（已有）：
  │   画面描述、shot_type、tags、OCR文字、主色
  │
  ├─ Audio 分析（新增）：
  │   ├─ ASR 转写 + 置信度评分 (0-1)
  │   ├─ 声音事件检测 + 置信度评分 (0-1)
  │   ├─ 整体音频质量评分 (0-1)：基于信噪比、音量稳定性
  │   └─ 音量/音高变化曲线
  │
  ├─ Context 分析（新增）：
  │   视频位置、前后关联、持续时间
  │
  └─ 多模态融合标注（音频权重动态调整）：
      音频整体质量 > 0.6 → 音频权重 = 0.4, 视觉权重 = 0.6
      音频整体质量 0.3-0.6 → 音频权重 = 0.2, 视觉权重 = 0.8
      音频整体质量 < 0.3 → 退化到纯视觉模式, 音频权重 = 0
```

**降级策略**：

| 音频质量 | 模式 | 行为 |
|---------|------|------|
| > 0.6（清晰） | 多模态融合 | Vision + Audio + Context 全权重 |
| 0.3-0.6（嘈杂） | 视觉优先 | Audio 降权，ASR/声音事件仅作参考 |
| < 0.3（无声/噪音） | 纯视觉退化 | 完全依赖 Vision + Context，提示用户"音频质量差，分析可能受限" |

**人工审核界面**：

在自动标注完成后，展示每个镜头的关键帧缩略图 + 标注结果 + 置信度：
- 置信度 > 80%：自动通过，绿色标记
- 置信度 50-80%：黄色标记，建议复核
- 置信度 < 50%：红色标记，必须人工确认

**行业模板库**：

| 行业 | Hook 典型模式 | Proof 典型模式 | CTA 典型模式 |
|------|-------------|---------------|-------------|
| 美妆 | 素颜→妆后对比、产品特写旋转 | 持妆测试、防水测试 | 优惠价格+赠品展示 |
| 3C | 开箱悬念、功能反转 | 跑分/实测数据、对比测试 | 限时折扣+参数标签 |
| 食品 | 食欲特写、配料揭秘 | 真材实料对比、口感描述 | 囤货装+到手价 |

### Phase 2：字幕系统重构

**目标**：分离配音文案和屏幕字幕。

#### 2.1 script 文本的三种用途

```
script: "家人们直接炸了！元气森林这波草本饮品真的赢麻了，
         四种口味全覆盖，配料表干干净净"

用途 1: TTS 配音 → 整句送给火山 TTS → 生成语音音频
用途 2: 屏幕字幕 → LLM 提炼为 "元气森林 · 4种口味 · 干净配料"
用途 3: 文案评审 → LLM 评估文案质量
```

#### 2.2 屏幕字幕生成规则

| 分镜类型 | 字幕内容 | 行数 | 位置 | 特效 |
|---------|---------|------|------|------|
| Hook | 产品名 或 冲突词 | 1行 | 居中偏上 | 弹入 |
| 叙事段 | 关键词提炼 | 1-2行 | 底部居中 | 淡入 |
| Proof | 数据 或 对比词 | 1-2行 | 底部居中 | 逐字出现 |
| CTA | 价格 + 行动号召 | 1行 | 居中 | 缩放弹入+金黄底色 |

#### 2.3 原视频字幕冲突处理 — v3 升级

**全片字幕检测**（Phase 0 阶段执行）：

```
分析原视频所有关键帧的 OCR 结果：
  ├─ 零散字幕（<30% 帧有文字）→ 单镜头替换策略（v2方案）
  ├─ 全程硬字幕（>70% 帧有文字，且风格统一）
  │     → 弹出询问："检测到原片自带专业字幕，是否保留原字幕风格？"
  │         ├─ 用户选"是" → 保留原字幕区域，用 delogo 尝试移除 + 同位置叠加新文字
  │         └─ 用户选"否" → 全部镜头走重组或AI生成
  └─ 无法判定 → 默认走重组策略，优先使用无字幕镜头
```

### Phase 3：镜头池重组引擎

**目标**：用原视频的真实镜头重新编排。

**Step 1: 镜头拆分**

```
原始视频 → PySceneDetect (自适应 threshold) → 12-20 个镜头

每个镜头包含：
{
  id, start_s, end_s, duration_s,
  mid_frame_path,
  vision: { shot_type, tags, ocr, description, dominant_colors },
  audio: { asr_text, confidence, sound_events, quality_score },
  context: { position, prev_type, next_type },
  quality: { sharpness, brightness, composition_score },
}
```

**Step 2: 镜头匹配**

```
目标分镜：Hook (需要 "恐惧好奇" 类开头, 2-3s)

多模态匹配分（音频权重根据质量动态调整）：
  scene_type == "hook" → +30
  hook_type 匹配 → +25
  audio置信度>0.6 且含惊呼/悬念词 → +20; 否则 +5
  时长在 1.5-3.5s → +15
  quality > 60 → +10

→ 最高分 > 60：使用该镜头
→ 40-60：候选，降级到"优化"
→ < 40：触发 AI 生成
```

**Step 3: 重组编排示例**

```
新结构: Hook(2s) → Scene(5s) → Product(4s) → Proof(3s) → Offer(2.5s) → CTA(2s)
  │
  ├─ Hook: 镜头#3 (匹配分 82) → 直接用
  ├─ Scene: 镜头#7(1.8s)+镜头#9(3.2s) → 拼接
  ├─ Product: 镜头#12(3.5s) → 裁切到4s + 放慢1.14x
  ├─ Proof: 镜头#5(4s) → 匹配分68 → 静音+混入TTS
  ├─ Offer: 无匹配 → AI生成
  └─ CTA: 无匹配 → AI生成
```

### Phase 4：音频驱动转场与节奏控制

**v3 新增：跨音频三层卡点体系**

视频有三层声音：原视频层（已静音）、TTS 配音层、背景音乐层。专业卡点需要在这三层之间找到最佳节奏。

#### 4.1 主节奏轨：TTS 优先

```
剪辑点 = 优先对齐(TTS 关键词语音尾)
         → 再对齐(BGM 节拍点, 偏移 ≤ ±0.15s)
         → 最后兜底(目标时长)

示例：
  TTS Hook 句尾: "差点毁了我的容！" → 语音结束于 2.08s
  BGM 最近节拍点: 2.0s (偏移 0.08s, 在 ±0.15s 内)
  目标切换点: 2.0s ← 同时满足 TTS 尾 + BPM 对齐
```

**实现要点**：
- TTS 合成时开启 `enable_timestamp`，获取字/词级时间戳
- 每个分镜的 TTS 最后一个音节结束时间 = 该分镜的理想切换点
- BPM 对齐作为次级约束，偏移不超过 ±0.15s
- 如果 BPM 节拍点与 TTS 尾偏移 > 0.15s，放弃 BPM 对齐，以 TTS 为准

#### 4.2 转场克制原则 — v3 新增

**硬切是最专业的转场。90% 的转场应为硬切和溶解。**

只在以下关键节点使用特殊转场：

| 允许特殊转场的节点 | 转场 | 原因 |
|------------------|------|------|
| 证明段 → 对比段 | 左右滑入 | 视觉强化"对比"概念 |
| 末段 → CTA | 缩放放大 | 聚焦转化，这是唯一需要"花哨"的点 |

**其余所有切换点 → 硬切或 0.15s 溶解**

**规则**：整个视频的特殊转场不超过 2 处。克制是专业剪辑的第一原则。

### Phase 5：色彩一致性 - LUT 方案

**v3 新增：产品色保护机制**

#### 5.1 产品色提取

在 Phase 1 的 Vision 分析中，如果识别到 `[产品]` 标签：
- 提取产品区域的 dominant_colors
- 标记为"受保护色"，存入 shot metadata

#### 5.2 LUT 应用 + 保护

```
Step 1: 分析主色调 → 推荐 LUT 预设

Step 2: 用户选择 LUT（或 AI 自动推荐）

Step 3: 应用 LUT
  ffmpeg -i segment.mp4 -vf "lut3d=preset.cube" output.mp4

Step 4: （可选）产品色保护
  如果用户开启"产品色保护"：
    对含产品镜头的输出帧做轻量颜色校正：
    ffmpeg -i output.mp4 -vf "colorbalance=rs=-0.02:gs=-0.02:bs=-0.02" final.mp4
    注意：这是非常微弱的回调，目的是防止 LUT 使品牌色严重跑偏，
    而非完全还原产品色。力度控制在 5% 以内。
```

#### 5.3 预设 LUT 列表

| LUT 名称 | 效果 | 适用场景 |
|---------|------|---------|
| 自然通透 | 微提亮+降饱和 | 日用品、食品 |
| 电影质感 | 暗角+暖色偏移 | 品牌故事、高端产品 |
| 清新明亮 | 提亮+冷色偏移 | 美妆护肤 |
| 高对比度 | 加深阴影+提亮高光 | 3C产品、科技 |
| 原片风格 | 轻微统一色调 | 保守策略，尽量少改动 |

### Phase 6：AI 视频生成精准调用

**触发条件**（满足任一即触发）：
1. 该分镜类型在 shot_pool 中完全无匹配（最高匹配分 < 40）
2. 原视频该维度的评分 < 30（内容太差，不值得复用）
3. Vision OCR 检测到该时间段原视频有字幕，且无替代镜头
4. 该镜头音频质量 < 0.2 且无字幕信息（画面和声音都不可用）

**不触发条件**：
1. shot_pool 中有匹配分 > 60 的镜头 → 用原视频
2. 该维度评分 > 50 且镜头 quality > 60 → 用原视频优化

## 四、实施优先级

```
Phase 0: 动态结构优化 (1天)
  ├─ LLM 分析产品 + 结构约束条件
  └─ 全片字幕检测（硬字幕/零散字幕/无字幕）

Phase 1: 多模态镜头理解 (1天)
  ├─ ASR + 声音事件 + 置信度评分
  ├─ 音频质量降级策略
  └─ 行业模板库 + 人工审核界面

Phase 2: 字幕系统重构 (1天)
  ├─ script → TTS 配音 + LLM 提炼屏幕关键词
  ├─ 全片硬字幕保留/替换策略
  └─ delogo + 同位叠加方案

Phase 3: 镜头池重组引擎 (2天)
  ├─ 细粒度拆分 + 多模态标注
  ├─ 动态权重镜头匹配算法
  └─ FFmpeg 重组渲染

Phase 4: 音频驱动转场 (1天)
  ├─ TTS 音素级时间戳 → 主节奏轨
  ├─ BPM 次级对齐（±0.15s）
  ├─ 特殊转场仅限 2 处（证明→对比 + 末段→CTA）
  └─ 其余全部硬切/0.15s 溶解

Phase 5: LUT 色彩方案 (0.5天)
  ├─ 5 种预设 LUT + AI 推荐
  └─ 产品色保护机制

Phase 6: AI视频精准调用 (0.5天)
  └─ 四条件触发 + 三条件跳过
```
