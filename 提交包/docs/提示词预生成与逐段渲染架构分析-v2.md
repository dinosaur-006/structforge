## 一、当前规则引擎 vs LLM 生成对比

### 1.1 同一分镜的提示词对比

**场景**: 趣多多饼干广告，Product 分镜，缓推·兴奋

**规则引擎生成** (当前):
```
vertical 9:16 composition, food photography, delicious gourmet, appetizing culinary presentation. 
premium hero product shot, beverage, drink, exquisite detail, glossy, sparkling, golden surface, slowly rotating on turntable. 
slow cinematic push-in, smooth elegant tracking, gradual reveal.
studio lighting, clean background.
commercial photography, photorealistic, 8k resolution, shallow depth of field, professional color grading
```

**LLM 可生成** (预期):
```
Close-up shot of Chips Ahoy chocolate chip cookies, rich dark chocolate chunks embedded in golden-brown cookie surface. 
Steam rising softly from freshly baked cookies. Warm studio lighting from 45-degree left, creating gentle shadows. 
Rustic wooden table surface with scattered cookie crumbs. 
Slow cinematic push-in towards the center cookie, revealing crispy texture and melting chocolate. 
Shallow depth of field, macro lens, 8k photorealistic food photography, commercial lighting setup
```

### 1.2 差异分析

| 维度 | 规则引擎 | LLM |
|------|------|------|
| 产品特异性 | ❌ 通用"beverage, drink" | ✅ 具体描述饼干质感 |
| 场景细节 | ❌ 模板化"slow rotating" | ✅ 木质桌子+碎屑+蒸汽 |
| 语言自然度 | ⚠️ 拼接式，逗号分隔 | ✅ 完整英文句子 |
| 品牌适配 | ❌ 无法引用产品名 | ✅ 可描述具体产品外观 |
| 上下文利用 | ⚠️ 只用 type/camera | ✅ 可用 script/visual/产品图Vision分析 |
| 生成速度 | 0ms (本地) | ~5-10s (LLM API) |
| API 成本 | 免费 | ~$0.02/段 |

**结论**: 规则引擎生成的是"任何食品都能用"的通用提示词。LLM 能根据实际产品生成专属提示词，效果显著更好。

## 二、用户提出的流程（LLM 按需生成）

```
用户进入结果页 → 看到 Storyboard Review + 分镜列表
  ↓
逐段选择: [🖼 生图] [🎬 生视频] [⏭ 跳过]
  ↓
点击"开始生成"
  ↓
对每个已选分镜:
  ① LLM 生成高质量 Flux 提示词 (~5s)
  ② ComfyUI 生成图片 (~60s)
  ③ 展示进度: "✅ 3/8"
  ↓
全部完成 → FFmpeg 拼接 → 视频播放
```

### 2.1 为什么 LLM 提示词更适配这个流程

**1. 可在运行时获得完整上下文**

LLM 调用时已有：
- 用户输入的产品名、卖点、调性
- Vision API 对产品图的分析（颜色、纹理、标签）
- 每个分镜的 script（口播文案）
- 每个分镜的 visual（LLM 描述的画面）
- 每个分镜的 camera/emotion/pace 参数

这些信息可以构建一个精准的 LLM prompt：

```
你是一位专业的 Flux AI 图片生成提示词工程师。
为客户的产品短视频广告创建图像生成提示词。

## 产品信息
名称: 趣多多巧克力曲奇
品类: 食品饮料 - 饼干零食
卖点: 真实巧克力豆, 香浓酥脆, 趣味包装
产品图分析: 金黄色饼干, 深棕色巧克力块, 红色包装盒, 暖色调

## 当前分镜
类型: product (产品展示)
口播文案: "真实抹茶粉融入香浓巧克力味，豆超多超美味"
画面描述: 白色背景下产品缓慢旋转，巧克力豆特写
运镜: 缓推
情绪: 兴奋

## 要求
- 纯英文提示词，适合 Flux Stable Diffusion
- 重点突出产品质感和新鲜感
- 80-150 词
- 包含: 主体描述、光照、景深、画质关键词

请直接输出提示词:
```

**2. 可根据用户选择动态调整**

- 用户选"生图"：生成静态产品照提示词
- 用户选"生视频"：生成带运镜描述的视频提示词（用于 WAN 2.2）
- 用户选"跳过"：不调 LLM，直接用原素材

## 三、性能分析

### 3.1 延迟计算

| 步骤 | 每段耗时 | 8 段总计 |
|------|:--:|:--:|
| LLM 生成提示词 | 5-10s | 40-80s |
| ComfyUI Flux 生图 | 40-80s | 5-10min |
| ComfyUI WAN 2.2 生视频 | 2-5min | (仅选中的) |
| FFmpeg 拼接 | 10s | 10s |
| **总计** | — | **6-12min** |

对比当前（规则引擎 + ComfyUI）：5-8min。LLM 额外增加 **40-80s**。

### 3.2 并行可行性

**LLM 提示词**: ✅ 可批量并行。8 个分镜同时调 LLM → 总量 ~10s。

**ComfyUI**: ❌ 不可靠并行。
- RunningHub 云端有并发限制，同时提交 8 个任务会触发 `TASK_QUEUE_MAXED`
- 自建 ComfyUI 受 GPU 显存限制（1 张卡通常只能同时跑 1-2 个）
- 实际只能**逐段串行**处理，每段 ~60s

**最终的每段时间线** (8 个分镜):

```
LLM 生成: ████ (10s, 8段并行)
ComfyUI:  ████████████████████████ ... ████ (8段 × 60s = 480s 串行)
FFmpeg:                                                      ██ (10s)
总耗时: ~500s ≈ 8 分钟
```

对比当前（规则引擎 + 串行 ComfyUI）: ~480s。LLM 额外贡献 ~10s（可忽略）。

## 四、架构对比

| 方案 | 提示词来源 | 时机 | 质量 | 延迟 | 复杂度 |
|------|:--:|------|:--:|:--:|:--:|
| **A: 当前** | 规则引擎 | 渲染时 | ⭐⭐ | 0ms | 低 |
| **B: 预生成 (v1)** | 规则引擎 | 迁移时 | ⭐⭐ | 0ms | 低 |
| **C: LLM 按需 (v2)** | Doubao LLM | 渲染时 | ⭐⭐⭐⭐⭐ | 5-10s/段 | 中 |
| **D: LLM 预生成** | Doubao LLM | 迁移时 | ⭐⭐⭐⭐⭐ | 0ms (预计算) | 中 |

### 推荐方案: C (LLM 按需)

**理由**:
1. 用户点击"开始生成"后有明确的等待预期
2. LLM 获得最完整的上下文（包括用户在产品页输入的最新信息）
3. 根据用户选择动态调整（生图 vs 生视频用不同提示词策略）
4. 避免预生成时"产品图还没上传"的信息缺失

### 实施要点

1. **LLM Prompt 设计**: 复用 DoubaoSeedClient + RobustLLMClient（已有基础设施）
2. **批量并行**: 8 段同时调 LLM，总计 ~10s
3. **降级链**: LLM 失败 → 规则引擎兜底（保证不阻塞）
4. **存储**: 生成的提示词存入 `render_jobs.metadata`，前端可展示
