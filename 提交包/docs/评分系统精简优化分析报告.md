## 一、当前评分系统全景

### 1.1 全部评分/分析系统清单

| 系统 | 位置 | 类型 | LLM? | 何时调用 | 耗时 |

## 二、每个系统的数据消费分析

### 2.1 CoverGenerator — ❌ 死数据

**调用链**:
```
pipeline.py L193-204:
  cover_gen = CoverGenerator(settings)
  cover_path = cover_gen.generate(structure, keyframe_paths=frames, product_name="")
  → 存入 result["meta"]["coverImagePath"]

前端: 无任何组件读取 coverImagePath
后端: VideoMeta.coverImagePath 字段存在但从未被 API 返回使用
```

**判定**: **死代码，立即删除**。封面图生成浪费 ~10s LLM 时间，产出数据从未展示。

---

### 2.2 HighlightDetector — ❌ 死数据

**调用链**:
```
pipeline.py L206-225:
  detector = HighlightDetector(...)
  highlights = detector.detect(rhythm_points, asr_segments, vision_frames, duration)
  → 存入 result["highlightMoments"]

前端: 无任何组件读取 highlightMoments
后端: VideoStructure.highlightMoments 字段存在但未被消费
```

**判定**: **死代码，立即删除**。高光检测浪费 ~10s LLM 时间。

---

### 2.3 BurstAuditor — ⚠️ 重复信息

**调用链**:
```
前端 AnalyzePage → POST /api/v1/audit/{jobId}
  → BurstAuditor.audit()
    → BurstMetricsCalculator (规则, 0ms)
    → LLM 软分析 (~15s)
  → 展示在 BurstAuditPanel

BurstMetricsCalculator 的相同数据也在:
  - migrator.py _build_audit_summary() (迁移时)
  - migrator.py generate() (预测评分)
  - render_pipeline.py _finalize() (自审计)
```

**问题**: BurstAuditor 的 LLM 调用与 BurstMetricsCalculator 的规则计算**产生高度重叠的信息**。前者多了一个 LLM 定性分析（"top_strength", "top_weakness", "suggestions"），但这个 LLM 分析在 AnalyzePage 中只是展示用，**不驱动任何下游决策**。

**判定**: 删除 BurstAuditor 的 LLM 调用，仅保留规则部分。省 ~15s。

---

### 2.4 ResultEvaluator 评审 — ⚠️ 可异步化

**调用链**:
```
migrator.py L279-288:
  review = self.evaluator.qualitative_review(script, before_scores={...})
  → LLM 调用 (~30s)
  → 存入 script.metadata.ai_review
  → 前端 AIReview 组件展示
```

**数据消费**: AIReview 组件确实展示此数据，但它是**信息展示**而非决策输入。迁移流程不需要等它完成就能继续。

**判定**: 保留，但改为异步（迁移返回后，后台补充评审数据）。

---

### 2.5 TransitionAdvisor — ⚠️ 低价值

**调用链**:
```
migrator.py L182-193:
  transition_advisor = TransitionAdvisor(...)
  trans_recs = transition_advisor.recommend_for_script(seg_dicts)
  for seg in script.segments:
    if seg.id in trans_recs and trans_recs[seg.id]:
      if not seg.transition or seg.transition == "硬切":
        seg.transition = best["transition"]
```

**分析**: 迁移时调 LLM 推荐转场，但大部分分镜的转场已经是 "硬切"（默认值），LLM 推荐的差异微乎其微。且 `_apply_type_defaults` 已为每个分镜类型设置了合适的 camera/emotion。

**判定**: 删除。省 ~10s。

---

### 2.6 ContentSafety — ⚠️ 默认关闭

当前 `content_safety_enabled = False`，代码不执行。保持现状即可。

## 三、精简方案

### 保留（3个关键路径）

| 系统 | 原因 | 耗时 |
|------|------|:--:|
| **Vision 分析** | 结构提取必需输入 | ~15s |
| **LLM 结构提取** | 核心分析，无可替代 | ~45s |
| **LLM 脚本迁移** | 核心生成，无可替代 | ~60s |
| **BurstMetricsCalculator** | 0ms 规则引擎，为 LLM 提供关键审计数据 | 0ms |
| **ResultEvaluator 基线** | 0ms 规则引擎，生成版本对比 | 0ms |

### 删除（4个）

| 系统 | 原因 | 节省 |
|------|------|:--:|
| **CoverGenerator** | 产出数据从未展示 | ~10s |
| **HighlightDetector** | 产出数据从未展示 | ~10s |
| **BurstAuditor LLM** | 数据与规则引擎重复 | ~15s |
| **TransitionAdvisor** | 低价值，已用规则替代 | ~10s |

### 改为异步（1个）

| 系统 | 当前 | 改进后 | 节省 |
|------|------|------|:--:|
| **ResultEvaluator 评审** | 同步阻塞 ~30s | 异步后台补充 | ~30s (迁移提前返回) |

## 四、效果预估

| 指标 | 当前 | 优化后 | 变化 |
|------|:--:|:--:|:--:|
| 分析阶段 LLM 调用数 | 4 | 2 | -50% |
| 分析阶段耗时 | ~80s | ~60s | -25% |
| 迁移阶段 LLM 调用数 | 4 | 1 | -75% |
| 迁移阶段耗时 | ~120s | ~60s | **-50%** |
| AnalysisPage LLM 调用 | 1 (BurstAuditor) | 0 | -100% |
| 死代码删除 | — | 4 个服务缩减 | - |

**核心收益**: 迁移从 ~120s 降至 ~60s（省掉同步的评审+转场 LLM 调用），分析从 ~80s 降至 ~60s（省掉封面+高光 LLM 调用），同时删除 ~15s 的审计页面 LLM 调用。

---

## 五、不影响的功能

以下功能**保持不变**：

- ✅ 视频结构分析的准确度（Vision + LLM）
- ✅ 脚本生成的 prompt 质量（BurstMetrics 审计数据仍在）
- ✅ AIReview 组件（改为异步后仍会展示）
- ✅ 版本对比指标（ResultEvaluator 基线保持）
- ✅ 渲染自审计（render_pipeline BurstMetrics 保持）
- ✅ AnalyzePage 审计展示（BurstAuditor 规则部分保持）
