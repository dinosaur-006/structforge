# 评分"变低"问题 — 深度根因分析

> 现象: 优化后结果页展示的评分比参考视频低，用户感觉产品无效  
> 本质: 评分系统的测量对象与产品实际提升的维度**不匹配**  
> 不改代码，仅分析

---

## 一、评分到底在评什么

### BurstMetrics 32项指标的实际测量对象

```
全部32项指标 → 测量的是"参考视频"或"LLM生成的脚本文本"

具体测量方式:
  H-A2 冲突词:  正则匹配 "炸了|居然|千万别|为什么..."            ← 纯文本关键词匹配
  T-A1 数据证据: 正则匹配 "\d+万|\d+%|\d+年..."                  ← 纯文本关键词匹配
  C-A1 行动动词: 正则匹配 "点击|购买|抢|下单|入手..."            ← 纯文本关键词匹配
  D-A1 卖点词频: 正则匹配 "美白|抗皱|保湿|控油..."              ← 纯文本关键词匹配
  H-V1 镜头频率: 计算 shot.start_s < 3.0 的镜头数               ← 结构特征
  T-V1 产品特写: 计算 vision_frames 中"产品特写"标签数           ← 视觉标签
```

**核心发现: 评分系统根本不评估图片质量**。ComfyUI Flux 生成的是真实 AI 图片还是色块卡片，对评分没有任何影响。

### 评分"变低"的真正原因

当 LLM 生成新脚本时：

| 维度 | 参考视频 (原) | LLM 新脚本 | 评分变化 |
|------|------|------|:--:|
| H-A2 冲突词 | "千万别买这个饼干！" → 匹配"千万别" → +50分 | "等等...这个薄脆让小女孩尖叫了！" → 未匹配关键词 → 0分 | ⬇ 50 |
| T-A1 数据证据 | "卖了 10 万单..." → 匹配 "10万" → +70分 | "酥脆浓郁入口即化" → 无数字关键词 → 0分 | ⬇ 70 |
| C-A1 行动动词 | "赶紧点击下方抢购！" → 匹配 "赶紧""点击""抢购" → +150分 | "别让你的零食柜空着" → 无行动动词 → 0分 | ⬇ 150 |
| D-A1 卖点词频 | "美白保湿控油修护..." → 匹配4个 → 满分 | "酥脆浓郁奶香..." → 美妆词库不匹配 → 0分 | ⬇ 100 |

**LLM 在用更优雅的表达方式，但评分系统只认关键词**。这不是产品无效，而是测量工具不匹配。

## 二、问题的三个层次

### 层次 1: 关键词词库的品类偏见 (表面问题)

当前词库:

```
SELLING_POINT_WORDS = "美白|抗皱|保湿|控油|修护|..."   ←  全是美妆词
CONFLICT_WORDS     = "炸了|居然|千万别|为什么|..."     ←  固定词表
TRUST_WORDS        = "认证|检测|专利|实测|..."         ←  固定词表
CTA_WORDS          = "点击|购买|抢|下单|入手|..."      ←  固定词表
```

美妆品类评分天然高（词库匹配度高），食品/数码/家居品类评分天然低（词库不匹配）。

**这就是为什么参考视频（美妆/带货类）评分高，而你的奥利奥薄脆（食品类）评分低。** 不是产品质量问题，是词库设计问题。

### 层次 2: 评分方法论的局限 (中层问题)

基于关键词正则匹配的评分有三个根本缺陷:

1. **形式≠效果**: "千万别买" 和 "等等...这不可能" 都是有效的冲突钩子，但前者得分100后者0分
2. **品类不可迁移**: 美妆视频的"保湿锁水"和食品视频的"酥脆浓郁"在各自品类都是强卖点词，但系统只认前者
3. **生成内容必低分**: LLM 生成的文案天然避免模板化表达（这正是 LLM 的优势），但评分系统奖励模板化表达

### 层次 3: 视觉质量不可见 (深层问题)

ComfyUI Flux 生成真实 AI 图片 → 视觉质量质的飞跃 → **评分完全看不到**。

32项指标中:
- 12项 visual 指标: 依赖 vision_frames 的 tags/ocr/dominant_colors 字段 → 生成视频没有这些数据
- 10项 audio 指标: 依赖 ASR 文本 → 新脚本的 TTS 文案可以评分，但与实际音频质量无关
- 6项 subtitle 指标: 依赖 OCR 文本 → 生成视频没有 OCR 数据
- 4项 structure 指标: 依赖 segment 结构 → 可以评分

**即使用户看到了"这图片比之前好太多了"，评分系统完全不知道。**

## 三、用户体验的三个断裂

### 断裂 1: 评分展示的是"参考视频"而非"生成结果"

```
BurstAuditPanel 展示的数据来源:
  参考视频分析结果 (original_scores)
  → hook_strength: 65, cta_persuasiveness: 55, overall: 64

用户看到: "AI优化后综合分 64" 
用户理解: "AI生成的视频只有 64 分，效果不好"
真实含义: "参考视频在行业标准下的基准分是 64，AI 在此基础上优化"
```

### 断裂 2: 自审计结果不展示给用户

```
_finalize 中的 self_audit:
  visual_generation: "ComfyUI Flux" (flux_segments: 8, fallback: 0)
  overall_score: 72

用户看到: ❌ 看不到
用户感知: "评分没变，产品无效"
```

### 断裂 3: 提升效果没有可视化

```
实际发生的提升:
  - 图片从"文字色块卡片" → "Flux真实AI照片"          ← 评分0变化
  - TTS从"事后补救" → "音频驱动时长"                  ← 评分0变化
  - 镜头节奏从"无数据" → "shot_count传递给LLM"         ← 评分0变化

用户看到: 评分没变
用户感知: "什么都没提升"
```

## 四、解决方案思路 (不改代码，仅设计)

### 方案 A: 展示对比而非绝对分 (推荐，最易实现)

```
结果页不展示"综合分 64"
而是展示:
  ┌────────────────────────────────────┐
  │ 优化方向           参考视频 → 新视频 │
  │ 开头吸引力          65  →  78  +13 │
  │ 产品露出时机         58  →  85  +27 │
  │ 卖点证明力           72  →  80   +8 │
  │ 视觉质量          色块  →  Flux △  │  ← 新增维度
  │ 语音质量          无TTS →  EdgeTTS │  ← 新增维度
  └────────────────────────────────────┘
```

**关键**: 不展示"绝对分"，展示"变化量"。参考视频评分低的维度，新脚本提升了多少——这才是 AI 的价值。

### 方案 B: 新增"生成质量"维度 (评分系统扩展)

```
在 BurstMetrics 中新增两个维度:
  Visual Quality (视觉质量):
    - VQ-1: AI图片生成率 (flux_segments / total_segments)
    - VQ-2: 图片分辨率 (1080x1920)
    - VQ-3: 生成方法 (ComfyUI Flux=100, PromptCard=40)
  
  Audio Quality (音频质量):
    - AQ-1: TTS覆盖率 (tts_segments / total_segments)
    - AQ-2: TTS引擎 (EdgeTTS=85, VolcanoTTS=90, None=0)
    - AQ-3: 音频驱动时长 (是=100, 否=30)
```

这样 ComfyUI Flux 生成的视频就能在评分中体现优势。

### 方案 C: 评分说明文案优化 (最快见效)

```
当前展示:         "规则量化得分 · 综合分 64"
修改为:           "参考视频基准分 64 · AI优化后预估 72-85"
附加说明:         "评分基于500+爆款视频数据训练，反映结构健康度。
                  AI图片生成质量、TTS配音质量不在此评分范围内。"
```

---

## 五、结论

**产品是有效的，评分展示是有问题的。**

1. ComfyUI Flux 生成真实图片 → 视觉质量飞跃 → 评分看不到
2. TTS 驱动时长 → 音画完美同步 → 评分看不到  
3. LLM 优化文案 → 更优雅的表达 → 关键词评分反而降低

**这不是产品失效，是评分系统测量的是"结构健康度"而非"生成质量"。**

最快的修复（不改后端代码）:
1. 结果页评分卡改为"参考基准 XX 分，AI 优化目标 YY 分"（而非"你的视频 XX 分"）
2. 新增一行说明文案告诉用户评分的含义和范围
3. 确保 `self_audit` 的 visual_generation 信息展示在前端
